# Software Requirements Specification (SRS) — MarketMind

## 1. Introduction

### 1.1 Purpose
This document specifies the software requirements for **MarketMind: Explainable Stock Market Intelligence & What-If Prediction Platform**. MarketMind is an educational and research-oriented full-stack analytical platform that combines Mathematics & Statistics, Machine Learning, Data Visualization, and Software Engineering principles.

### 1.2 Scope
MarketMind ingests historical stock market datasets, performs descriptive and inferential statistical modeling, engineers leakage-free technical features, trains and registers multiple supervised and unsupervised machine learning models, generates directional predictions with calibrated probabilities and risk assessments, provides local and global model explainability (SHAP / feature attribution), executes chronological walk-forward backtests, and supports interactive what-if scenario simulations.

### 1.3 Disclaimer
MarketMind is strictly an educational and research analytics tool. Predictions, probabilities, risk indicators, and what-if simulations are generated by statistical and machine learning models subject to uncertainty and data limits. MarketMind does not provide personalized investment advice or guarantee financial outcomes.

## 2. Overall Description

### 2.1 Product Perspective
MarketMind follows a modular layered architecture:
- **Presentation Layer**: React 18 + TypeScript + Tailwind CSS + Plotly/Recharts for rich financial data visualization.
- **API Gateway Layer**: FastAPI service with Pydantic v2 validation and structured error handling.
- **Application & Domain Layer**: Dedicated engines for Statistics, Feature Engineering, ML Training/Inference, Risk Assessment, Explainability (SHAP), Chronological Backtesting, and What-If Simulation.
- **Data & Persistence Layer**: PostgreSQL with SQLAlchemy 2 ORM, Alembic migrations, and local/file-based model artifact storage (`models/artifacts/`).

### 2.2 User Characteristics
- **Students & Academic Evaluators**: Exploring mathematical foundations, ML pipelines, and software engineering practices.
- **Data Analysts & Researchers**: Evaluating model reliability, feature contributions, and walk-forward historical evaluations.

### 2.3 Operating Environment
- Operating System: Cross-platform (Windows, Linux, macOS)
- Python Runtime: Python 3.11+
- Node.js Runtime: Node.js 18+
- Database: PostgreSQL 16+ (or SQLite for isolated local test runs)

## 3. Specific Requirements & Module Specifications

### 3.1 Module 1: Data Ingestion & Storage (FR-01)
- **Input**: Historical stock datasets (CSV / API format) containing `date`, `open`, `high`, `low`, `close`, `adjusted_close`, `volume`, `symbol`, `company_name`, `exchange`, `currency`.
- **Validation**: Strict schema checks, missing dates identification, duplicate detection, OHLC validity rules ($high \ge low$, $high \ge open$, $high \ge close$, $volume \ge 0$).
- **Immutability**: Raw data stored immutably in `data/raw/`. Validated/cleaned data stored in `data/validated/` and database tables with checksums.

### 3.2 Module 2: Data Leakage Prevention (FR-02)
- **Time-Series Integrity**: Chronological train/validation/test splits without random shuffling.
- **Transformation Isolation**: Scalers and imputers fitted strictly on training data bounds.
- **Rolling Windows**: Features calculated using only data available at or prior to the feature timestamp.
- **Cutoff Auditability**: Every prediction records an exact point-in-time data cutoff timestamp.

### 3.3 Module 3: Mathematical & Statistical Engine (FR-03)
- **Descriptive Metrics**: Mean, median, mode, variance, standard deviation, min, max, range, skewness, kurtosis.
- **Returns**: Simple daily returns $R_t = (P_t - P_{t-1}) / P_{t-1}$ and log returns $R_t = \ln(P_t / P_{t-1})$.
- **Probability Modeling**: Return distribution histograms, fitted normal curve, empirical probabilities $P(R > 0)$ and $P(R < 0)$, Value-at-Risk (VaR).
- **Correlation & Scatter**: Pearson/Spearman correlation matrices across stocks, volumes, and market index returns.
- **Hypothesis Testing**: Formal two-sample hypothesis testing ($H_0, H_1, \alpha$, test statistic, p-value, decision, interpretation).

### 3.4 Module 4: Feature Engineering Pipeline (FR-04)
- **Derived Features**: Lagged returns (1, 2, 5 days), rolling averages (5, 20 days), rolling volatility (5, 20 days standard deviation), rate-of-change momentum, volume change, rolling volume, market index returns, and market beta/correlation.
- **Feature Versioning**: Distinct hash and version identifiers (e.g., `features-v1.0`) recorded with each model run.

### 3.5 Module 5: Machine Learning Engine & Model Laboratory (FR-05)
- **Abstract Model Interface**: Standardized `BaseModel` contract supporting `train`, `predict`, `predict_proba`, `evaluate`, `save`, `load`, and `get_feature_importance`.
- **Baseline Models**: Majority class classifier and random walk / naive return regressor.
- **Classification Models (Target: UP/DOWN direction)**:
  - Logistic Regression (L2 penalty)
  - Support Vector Machine (Linear / RBF kernel with Platt scaling probability calibration)
  - Decision Tree Classifier
  - Random Forest Classifier (Ensemble)
- **Regression Models (Target: Expected Return %)**:
  - Linear Regression / Ridge Regression
  - Random Forest Regressor
- **Unsupervised Learning & Dimensionality Reduction**:
  - K-Means Clustering for Market Regime Discovery (Low Volatility, High Volatility, High Momentum, High Volume).
  - Principal Component Analysis (PCA) for 2D/3D projection and variance explanation.

### 3.6 Module 6: Model Evaluation & Registry (FR-06)
- **Classification Metrics**: Accuracy, Precision, Recall, F1 Score, Confusion Matrix, Brier Score.
- **Regression Metrics**: Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), $R^2$.
- **Model Registry**: Tracking model ID, version, dataset version, feature version, hyperparameters, training period, metrics, artifact URI, and creation timestamp.

### 3.7 Module 7: Prediction Engine (FR-07)
- **Output Schema**: Predicted Direction (`UP` / `DOWN`), Direction Probability (e.g. 71.4%), Expected Return (+1.2%), Risk Level (`LOW` / `MEDIUM` / `HIGH`), Model Version, Data Cutoff Timestamp, Prediction Generated Timestamp.

### 3.8 Module 8: Explainable AI Engine (FR-08)
- **Global Feature Importance**: Relative feature weights across the dataset.
- **Local Feature Explanations (SHAP)**: Instance-level Shapley values explaining individual predictions.
- **Partial Dependence**: Visualizing how prediction probability changes across feature ranges.
- **Natural Language Interpretation**: Plain-English explanation generated directly from contribution data.

### 3.9 Module 9: Backtesting & Walk-Forward Engine (FR-09)
- **Walk-Forward Splitting**: Multi-fold chronological evaluation (e.g. Fold 1: Train 2021-2022 ➔ Test 2023, Fold 2: Train 2021-2023 ➔ Test 2024, Fold 3: Train 2021-2024 ➔ Test 2025).
- **Evaluation Tracking**: Actual vs Predicted comparison, fold metrics, out-of-sample confusion matrices, and cumulative return comparison against buy-and-hold baseline.

### 3.10 Module 10: What-If Scenario Simulator (FR-10)
- **Controlled Input Adjustments**: Market Return delta $[-10\% \dots +10\%]$, Volume delta $[-50\% \dots +50\%]$, Volatility delta $[-50\% \dots +50\%]$, Momentum delta $[-50\% \dots +50\%]$.
- **Comparative Analysis**: Side-by-side Baseline vs Scenario display showing probability change, return change, and sensitivity breakdown.

## 4. Non-Functional Requirements

- **NFR-01 Performance**: Standard analytical API endpoints respond within $< 1.5$ seconds for standard stock histories.
- **NFR-02 Security**: Zero credential hardcoding; all configuration loaded from environment variables (`.env`).
- **NFR-03 Usability**: Responsive dark-mode financial dashboard adhering to accessibility guidelines (contrast, keyboard navigation, tooltips).
- **NFR-04 Reproducibility**: Fixed random seeds and strict version logging ensuring identical model training and prediction outputs.
